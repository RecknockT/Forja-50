# Revisión de motores, modelos y Windows · 21 de octubre de 2026

Consulta de GitHub, Hugging Face, documentación de autores y reportes de usuarios. Alcance: una RTX 5080 o 5070 Ti de escritorio de 16 GB, Windows y aproximadamente 32 GB de RAM. No se instalaron candidatos, descargaron pesos ni ejecutaron pruebas de inferencia. Los resultados externos no son mediciones de Forja.

La validación v1.5 de Todd alcanza 128K en Linux; no acredita automáticamente esas mejoras en el port Windows. ## Candidato principal para comparar: Windows de Ryan / NInfer-all

La [guía del autor](https://github.com/Ryan-gsq/ninfer-16g-5070ti-5080-5090-qwen3.8-27b-gsq-rco/blob/main/docs/rtx-5070ti-windows.en.md) documenta Windows 11, 5070 Ti, 32 GB RAM y CUDA 13.4.2. Usa Swift GSQ-RCO en contenedores v3: S a 128K y XXS a 160K. Son otros pesos y otro motor.

| Caso externo | Entrada real | Generación | Decodificación observada |
| --- | --- | --- | --- |
| S 64K | 62.439 tokens | 512 | 96–106 tokens/s |
| S 128K | 127.970 tokens | 512 | 92–98 tokens/s |
| XXS 160K | 160.726 tokens | 512 | 83–91 tokens/s |

Tres repeticiones por caso; todas produjeron solo razonamiento. Los casos grandes dejaron unos 160–177 MiB libres según NVML, con comprobaciones CUDA llegando a cero. Eso prueba capacidad bajo esas condiciones, no calidad de programación, respuestas completas ni estabilidad con otras aplicaciones. La calibración publicada corresponde a la 5070 Ti; la 5080 necesita la suya. Fuente: guía anterior, pruebas del 30 de septiembre.

## Novedad reciente: Condor, antes Glyd

El [repositorio actual](https://github.com/surya-koritala/condor) ya anuncia Windows y 32–64 GB RAM para Qwen3.8-Flash-Next. El modo fast necesita unos 66 GB de descarga y 73 GB libres; precise/best requieren 64 GB RAM. Su Windows probado es una L4 de 24 GB, no una GeForce. Las cifras principales de velocidad corresponden a Ubuntu y una 4080 SUPER. El autor reconoce menor calidad de código largo en fast y una prueba de herramientas que puede fallar.

La [publicación visible v0.2.3](https://github.com/surya-koritala/condor/releases/tag/v0.2.3), del 20 de octubre, incluye EXE/DLL de Windows. El README ya cita mediciones de una compilación v0.2.4 del día 21: no confundir esas mediciones con los assets v0.2.3. La publicación reconoce dos fallos de herramientas en fast.

El motor tiene [BUSL 1.1](https://github.com/surya-koritala/condor/blob/main/ENGINE-LICENSE), con condiciones distintas para uso personal y producción comercial; los scripts Apache no convierten el motor en Apache. Esto requiere revisión antes de incorporarlo a un producto distribuido. No se integró.

## Otros candidatos y sus límites

- **Bonsai 2 27B**: [artefacto de 8,87 GiB](https://huggingface.co/WaveCut/Ternary-Bonsai-2-27B-NInfer-v3), con MTP/DFlash2. La ficha publica HumanEval 90,9 en su evaluación y pruebas sobre otras GPU; no una comparación de agente con nuestro modelo en estas dos tarjetas. Necesita NInfer-all y formatos propios que el motor de Forja no admite. Interesante para obtener margen de memoria, pendiente de medir calidad y Windows de 16 GB.
- **mtrskeen para 5080**: [archivo de 15.514.935.296 bytes](https://huggingface.co/mtrskeen/qwen3.8-27b-ninfer-minq4-mtpq4-visionq4-5080), unos 0,95 GB menor que el de Todd. Publica texto hasta 124.928 tokens, KV i4, MTP-3, prefill 256 y gráficos CUDA apagados. Sus [mediciones](https://github.com/mtrskeen/ninfer-5080/blob/master/docs/BENCHMARKS.md) corresponden a Linux; no trasladar sus parámetros al motor actual sin validar compatibilidad y calidad.
- **natpate Windows 0.9.1**: [publicación del 29 de septiembre](https://github.com/natpate/ninfer-windows/releases/tag/v0.9.1), port nativo con dependencias incluidas, orientado a 5090 de 32 GB y contenedores v3. No es una sustitución validada para 16 GB; los archivos v2 necesitan conversión.
- **BeeLlama / derivados**: [KVarN y precisión especial para tokens recientes](https://github.com/kaelow/qwenllama.cpp), otro camino para reducir KV usando GGUF. Las tablas de ese README corresponden a Qwen3.6 en una 3090. No prueban una mejora de Forja con Qwen3.8 en 5080.
- **Flash-Next completo**: la [ficha de Qwen](https://huggingface.co/Qwen/Qwen3.8-Flash-Next) describe 125B, más 51B de embeddings y 4B de MTP. La descarga y la memoria total siguen importando aunque solo active parte de los expertos. No entra como reemplazo directo del 27B actual; Condor es una propuesta específica para repartirlo entre CPU, RAM y GPU.

## Decisión propuesta para la próxima etapa

Priorizar Node y Git con integridad y pruebas de integración; después comparar la base actual contra Ryan S/XXS y Bonsai en las mismas tareas. Condor merece una evaluación separada por su descarga, CPU, licencia y limitaciones del modo de 32 GB. Ninguna cifra de terceros permite declarar hoy una configuración ganadora para Forja.

La comparación debe medir respuestas finales, llamadas a herramientas y cambios Git correctos, además de velocidad: misma tarea, entrada efectiva, primera respuesta, generación, RAM y VRAM dedicada/compartida, con escritorio normal y sesiones prolongadas. Comenzar por 64K y medir después los límites. Descargar a mayor velocidad no reduce el tiempo de cargar pesos, procesar contexto ni compilar el motor.
